### 2. 可能的原因

**假设 A: Agent 有预测能力**
- Agent 可能在价格低点买入、高点卖出
- 我们的限价单只是被动等待，没有时机选择

**假设 B: Agent 数据是"后见之明"**
- Agent 交易记录可能是在 OHLC 范围内"选择"最优价格
- 这不是真实的前向测试（forward test）

**假设 C: 数据匹配问题**
- 我们使用 1 分钟 OHLC，但 agent 可能在更细粒度上执行
- Agent 价格可能来自 tick 数据，而非 1 分钟 bar

```python

    fill at limit_price
```

## 💡 启示与建议

### 1. Agent 不是"执行"问题，是"时机"问题

**关键洞察**：
- Agent 的 84.9% 胜率说明它**选择正确的交易时间**
- 我们的优化应该聚焦于**何时交易**，而非**如何执行**

### 2. 需要整合时机预测

当前策略的缺陷：
- ❌ 被动等待（每个 bar 都下单）
- ❌ 固定限价距离（不根据波动率调整）
- ❌ 没有市场状态判断

改进方向：
- ✅ 使用 ePDF 预测**何时**有限价单成交机会
- ✅ 根据波动率动态调整限价距离
- ✅ 结合市场状态（高/低波动）决定是否交易

### 3. Agent 数据可能不是"真实"执行

**怀疑点**：
- 99% 胜率（HeatingOil）在现实中几乎不可能
- 所有资产都显示类似的超高胜率
- 可能使用了后见之明（look-ahead bias）

**建议**：
- 验证 agent 数据来源
- 确认是否为真实执行记录
- 检查是否有数据质量问题
